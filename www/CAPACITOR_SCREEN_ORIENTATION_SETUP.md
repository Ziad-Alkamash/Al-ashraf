# تفعيل الاتجاه الأفقي الحقيقي (زي التطبيقات الكبيرة)

## ليه ده مطلوب؟
كل المحاولات اللي عملناها لحد دلوقتي (تدوير الصفحة بصريًا بـ CSS) هي "حيلة"
بديلة بتتفعّل بس لما القفل الحقيقي لاتجاه الشاشة يفشل. وهو بيفشل في تطبيقك
غالبًا لسبب واحد: الـ Activity الأصلي في AndroidManifest.xml مقفول على
`portrait`، فمهما حاول الجافاسكريبت يقفل landscape، أندرويد نفسه بيرفض.

الحل الصحيح (زي كل التطبيقات الكبيرة): نتحكم في اتجاه الشاشة من الطبقة
الأصلية (Native) نفسها عبر إضافة Capacitor الرسمية، مش عبر حيلة CSS.

## الخطوات

### 1) تركيب الإضافة
في مجلد مشروع Capacitor (مش مجلد الويب ده):

```bash
npm install @capacitor/screen-orientation
npx cap sync android
```

### 2) السماح للـ Activity بتغيير الاتجاه
افتح:
`android/app/src/main/AndroidManifest.xml`

ودوّر على الـ `<activity>` الرئيسي بتاع التطبيق (غالبًا `.MainActivity`)،
هتلاقي سطر زي:

```xml
android:screenOrientation="portrait"
```

غيّره لـ:

```xml
android:screenOrientation="unspecified"
```

**مهم:** لو السطر ده فضل `portrait`، الإضافة نفسها هترفض تقفل landscape
برضو (نفس المشكلة الأصلية)، فالخطوة دي إلزامية مش اختيارية.

### 3) إعادة البناء
```bash
npx cap sync android
```
وبعدين ابني الـ APK تاني من Android Studio زي ما بتعمل عادي.

## بعد كده
كود الويب في الملفات دي (app.js) بيحاول يستخدم الإضافة دي تلقائيًا لو
لقاها متاحة (`window.Capacitor.Plugins.ScreenOrientation`)، وبيرجع لبديل
الـ CSS القديم بس لو مش متركّبة أو الجهاز مش بيدعمها. يعني مفيش أي تعديل
تاني مطلوب في الكود — بمجرد ما تعمل الخطوتين فوق، زرار "قلب الصفحة بالعرض"
هيستخدم القفل الحقيقي لاتجاه الشاشة، ومنه:
- الهيدر والمحتوى هيدوروا مع بعض طبيعي (لأنهم فعليًا بقوا في شاشة landscape
  حقيقية، مش حيلة بصرية)
- السكرول هيشتغل عادي جدًا زي أي صفحة landscape طبيعية
- مفيش أي مشاكل توقيت أو محاور لمس غريبة

لو مش عايز تعمل التغيير ده دلوقتي، التطبيق هيفضل شغال ببديل الـ CSS
(المحسّن في هذا الإصدار)، بس ده هيفضل الحل الأضعف والأعرض للمشاكل.
