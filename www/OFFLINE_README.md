# نظام صفحات المصحف بدون إنترنت — دليل التركيب

## الوضع الحالي

اكتشفنا إن مستودع `quran-qcf4` اللي حمّلته يحتوي فعليًا على:
- `pages/001.json ... 604.json` → بيانات **رسم مصحف المدينة (QCF4)**
- `fonts-woff2/*.woff2` → كل **الخطوط** المستخدمة في الرسم

بيانات الصفحات والخطوط لا تُضمّن داخل التطبيق. عند أول تشغيل على Android/iOS،
تُنزّل بيانات النص والتخطيط وخطوط QCF4 إلى مساحة التطبيق الخاصة، ثم تصبح متاحة
للتقليب السريع والقراءة دون اتصال. يحتاج التنزيل الأول إلى اتصال بالإنترنت.

## الملفات

| الملف | الحالة | الوظيفة |
|---|---|---|
| `quran-offline.js` | **جديد** | المحرك: يفحص/يحمّل/يقرأ نصوص صفحات المصحف عبر Capacitor Filesystem + Preferences |
| `quran-api.js` | **معدَّل** | `getPage()` و`getPageQCF4()` يقرآن من التخزين الدائم بعد التنزيل، مع رجوع للشبكة عند الحاجة |
| `app.js` | **معدَّل** | خطوط QCF4 تُنزّل وتُخزّن محليًا، وتظل شاشة التنزيل الأولي مفعّلة |
| `index.html` | **معدَّل** | إضافة `<script src="quran-offline.js">` قبل `quran-api.js`/`app.js`، وإضافة عنصر `#quran-offline-gate` (شاشة التحميل الإلزامي) |
| `style.css` | **معدَّل** | تنسيق بسيط لـ `#quran-offline-gate` معتمد بالكامل على متغيرات الألوان والخطوط الموجودة أصلاً (لم يُغيَّر أي تصميم قائم) |

## كيف يعمل عند التشغيل (بالضبط كما طلبت)

1. عند فتح التطبيق، `initOfflineGate()` تتحقق:
   - لو التطبيق شغّال في متصفح/PWA عادي (بدون Capacitor) → يتجاوز الحاجز
     تمامًا، ويعمل التطبيق بنفس سلوكه القديم (قراءة مباشرة من الشبكة).
   - لو داخل تطبيق أندرويد/آيفون حقيقي:
     - يفحص `Preferences` (`quran_pages_downloaded`) **و** يتأكد فعليًا إن
       عيّنة من الملفات موجودة عبر `Filesystem.stat` (وليس فقط تصديق
       العلامة المخزَّنة).
     - لو كل شيء سليم → يختفي الحاجز فورًا ويكمل التطبيق طبيعي.
     - لو غير موجودة/ناقصة → يظهر حاجز التحميل الإلزامي مع زر
       "تحميل صفحات المصحف".
2. عند الضغط على الزر: تحميل صفحات النص والتخطيط وخطوط QCF4 بتزامن (concurrency) مع شريط تقدّم
   حقيقي، وإعادة محاولة تلقائية لأي صفحة تفشل (حتى 4 محاولات)، وزر "إلغاء"
   شغّال فعليًا عبر `AbortController`.
3. عند الاكتمال: تُحفظ ملفات الصفحات والخطوط وفهرس الآيات داخل تخزين
   التطبيق الخاص (`Directory.Data`)، وتُسجَّل العلامة `quran_pages_downloaded
   = true` في `Preferences`، ويختفي الحاجز.
4. من حينها، `QuranAPI.getPage()` و`getPageQCF4()` وخطوط الرسم تقرأ محليًا —
   **بدون اتصال بالإنترنت** بعد اكتمال التنزيل.
5. لو حُذفت الملفات لاحقًا (تنظيف يدوي، مساحة تخزين...)، `isDownloaded()`
   هتكتشف النقص تلقائيًا في المرة الجاية وتُظهر الحاجز مرة أخرى لإعادة التحميل.

نفس الزر موجود أيضًا داخل الإعدادات (`#btn-download-offline`) لإعادة التحميل
يدويًا في أي وقت — يستخدم بالضبط نفس المنطق (`runOfflineDownload`).

## حزم npm المطلوبة

نفّذ هذا داخل **مشروع Capacitor** نفسه (مش مجلد `www`):

```bash
npm install @capacitor/filesystem @capacitor/preferences
npx cap sync android
```

> ملحوظة: الكود بيستخدم `window.Capacitor.Plugins.Filesystem` و
> `window.Capacitor.Plugins.Preferences` مباشرة (بدون `import`)، لأن هذا
> مشروع بدون Bundler. طالما نفّذت `npm install` + `npx cap sync`، البلجنين
> هيتسجّلوا تلقائيًا ويبقوا متاحين على `window.Capacitor.Plugins` جوه
> WebView بمجرد تشغيل التطبيق على الجهاز/المحاكي — مفيش أي كود إضافي مطلوب
> لتفعيلهم.

لا حاجة لـ JSZip أو أي مكتبة فك ضغط، فالتحميل عبارة عن ملفات JSON وخطوط فردية.

## معالجة الأخطاء المطبَّقة

- **لا اتصال بالإنترنت**: رسالة واضحة قبل بدء أي طلب شبكة (`navigator.onLine`).
- **انقطاع أثناء التحميل**: كل صفحة فيها `timeout` (15 ثانية) + حتى 4 محاولات
  تلقائية بفاصل زمني متصاعد (350ms, 700ms, 1050ms) قبل اعتبارها فاشلة نهائيًا.
- **فشل جزئي**: لو فضلت صفحات فاشلة بعد كل المحاولات، الزر يرجع "تحميل" مع
  رسالة توضّح العدد، ومفيش علامة "مكتمل" تتسجّل إلا لو كل الصفحات نجحت 100%.
- **إلغاء المستخدم**: زر الإلغاء يوقف كل الطلبات الجارية فورًا عبر
  `AbortController` (مش انتظار انتهائها).
- **تحقق تكامل عند كل تشغيل**: عيّنة من 7 صفحات موزّعة على المصحف تُفحص
  فعليًا (`Filesystem.stat`) قبل الوثوق بعلامة "مكتمل" المخزَّنة.
- **مساحة تخزين ممتلئة**: أي فشل في `Filesystem.writeFile` يُعامَل كفشل
  عادي للصفحة (يدخل في نظام إعادة المحاولة نفسه).

## تحديث: التلاوة الصوتية (القرّاء) — تحويلها لـ Capacitor Filesystem

نظام تحميل/تشغيل الصوتيات الحالي (تحميل سورة بسورة، قوائم التشغيل، تحميل
قارئ كامل...) **ظل اختياريًا تمامًا كما هو** (مفيش حاجز إجباري للصوت) — بس
بقى مبنيًا فعليًا على Capacitor Filesystem بدل Cache Storage.

### الملف الجديد: `quran-audio-offline.js`

بدل ما أعيد كتابة كل دوال الصوت (تحميل/حذف/تشغيل/قوائم — أكتر من 10 أماكن
في app.js)، عملت **طبقة توافق (shim)** بنفس واجهة `Cache API` القياسية
(`match` / `put` / `delete` / `keys`) لكنها مخزَّنة فعليًا في:
```
Quran/audio/index.json          ← فهرس يربط كل رابط صوت بملفه المحلي
Quran/audio/<hash>.bin           ← ملفات الصوت الفعلية
```
داخل `Directory.Data` (نفس تخزين نصوص المصحف).

النتيجة: أي كود موجود بالفعل بيستخدم:
```js
const cache = await caches.open(AUDIO_CACHE_NAME);
await cache.match(url) / cache.put(url, response) / cache.delete(url) / cache.keys()
```
اتبدّل بسطر واحد بس:
```js
const cache = await QuranAudioOffline.openAudioStore(AUDIO_CACHE_NAME);
```
ونفس المنطق اللي بعده يشتغل زي ما هو **بدون أي تغيير** — لأن الكائن الراجع
بيتصرف بنفس الشكل تمامًا (سواء داخل تطبيق أندرويد/آيفون فبيستخدم Filesystem
فعليًا، أو داخل متصفح/PWA عادي فبيستخدم `caches.open()` الحقيقي زي الأول).

### إيه اللي اتغيّر فعليًا في app.js
- كل الأماكن الـ 8 اللي كانت بتعمل `caches.open(AUDIO_CACHE_NAME)` بقت
  `QuranAudioOffline.openAudioStore(AUDIO_CACHE_NAME)`.
- كل فحوصات الدعم `if (!('caches' in window))` بقت
  `if (!audioStorageSupported())` (بتتحقق من Filesystem **أو** Cache Storage).
- كل الميزات الموجودة فعلاً ظلت كما هي بدون أي تغيير في السلوك أو الواجهة:
  تحميل سورة مفردة، تحميل قارئ كامل (١١٤ سورة)، تحميل آية-بآية للقراء
  اللي عندهم تسجيل دقيق، قوائم التشغيل المخصّصة، وعرض "القرّاء المحمّلون".

### ليه الطريقة دي أفضل هنا (وليس نظام تحميل إجباري كامل)؟
الصوتيات كبيرة جدًا (قد تصل لعدة جيجابايت لو كل القرّاء)، فحاجز إجباري
"حمّل كل القرّاء الأول" هيضطر أي مستخدم يحمّل مئات الميجا/جيجا قبل ما يفتح
التطبيق حتى لو مش محتاج غير قارئ واحد — ده كان هيبوّظ تجربة الاستخدام. الوضع
الحالي (اختياري + Filesystem حقيقي) بيدّي نفس ضمان "يشتغل بدون إنترنت بعد
التحميل" لكل سورة/قارئ يختاره المستخدم بنفسه، بنفس متانة نظام صفحات النص.

### حزم npm إضافية مطلوبة للصوت؟
لا — نفس الحزمتين المذكورتين فوق (`@capacitor/filesystem` كافية، الصوت
مايحتاجش `@capacitor/preferences` لأنه مابيسجّلش علامة "تحميل كامل"، بس
لسه المكتبة نفسها مُثبَّتة أصلاً من قبل).

## تحديث: قسم "القارئ المختار" + اكتمال تحميل القارئ (المرحلة ١)

### 1) القارئ المختار (بدل "القارئ الافتراضي" في الإعدادات)
- اتشال قسم "القارئ الافتراضي" بالكامل من صفحة الإعدادات.
- ضيف بدل منه قسم **"القارئ المختار"** أعلى صفحة "الصوتيات" (فوق "القرّاء
  المحمّلون" مباشرة)، وهو نفس آلية `getSelectedReciter()` الموجودة أصلاً
  (قارئ واحد بس، مستخدَم في كل أنحاء التطبيق) — بس نقلنا مكان اختياره بس.
- اختيار قارئ من هنا بيتزامن فورًا مع أي مكان تاني بيستخدم نفس القارئ
  (استماع آية مفردة، القوائم الافتراضية...) لأنه نفس المفتاح بالظبط
  (`almus-hraf:reciter`).

### 2) اكتمال تحميل القارئ (زر "تشغيل المصحف كاملاً" + علامة صح بنية)
- لو الـ ١١٤ سورة كلها محمَّلة لقارئ معيّن (سواء بـ"تحميل الكل" أو بتحميل كل
  سورة يدويًا واحدة واحدة)، زر "تحميل الكل" أعلى صفحة سوره بيتبدّل تلقائيًا
  لزر **"محمَّل بالكامل ✓ — تشغيل المصحف كاملاً"**، والضغط عليه يشغّل من
  السورة الأولى وتكمل الباقي تلقائيًا وراها (نفس منطق "التشغيل المتواصل"
  الموجود بالفعل بشكل افتراضي).
- ظهرت علامة ✓ بدائرة بنية (`--gold-deep`) بجانب اسم القارئ في قائمتَي
  "القرّاء المحمّلون" و"كل القرّاء" لما يكتمل تحميله بالكامل.
- لون أيقونة "محمّلة" أمام كل سورة مفردة اتغيّر من وردي لبني/ذهبي (نفس
  هوية الألوان في التطبيق).

### الملفات المتأثرة في هذه المرحلة
`index.html`, `app.js`, `style.css` (نفس النسخ المرفوعة أسفل — استبدلهم زي العادة).

### المرحلة الجايّة
المشغّل الصوتي الاحترافي الجديد (زي الصورة اللي بعتها) هيستبدل المشغّل
الحالي في كل مكان في التطبيق — هتيجي في رد منفصل لضخامتها.

## إصلاح عاجل: القارئ المختار متراكب + "غير محمّلة" رغم التحميل

آسف على الحاجتين دول — سببهم اتحدد بالظبط وهم مُصلَحين دلوقتي في نفس
الملفات المرفوعة تحت (استبدلهم زي العادة):

### 1) تراكب قائمة "القارئ المختار"
السبب: قائمة اختيار القارئ (نفس الكومبوننت المستخدم في الإعدادات) كانت
لها تنسيق (خلفية/حدود/ظل) مربوط فقط بـ `#settings-overlay` و`#player-overlay`
في CSS. لما نقلتها لمكان جديد (`#downloaded-audio-overlay`) من غير ما أضيف
نفس التنسيق ليه، القائمة فضلت بتفتح فعليًا لكن **شفافة تمامًا** فبان نص
الصفحة اللي تحتها متراكب فوق نص القائمة نفسها. اتصلح بإضافة نفس التنسيق
لـ`#downloaded-audio-overlay` كمان.

### 2) السور بتظهر "غير محمّلة" رغم إنها اتحمّلت فعلاً
ده باگ أعمق وأقدم من تعديلاتنا، لكن ظهر بوضوح دلوقتي: أغلب القرّاء (زي ياسر
الدوسري) بيتحمّلوا **آية بآية** (ملفات دقيقة منفصلة)، مش كملف سورة كاملة
واحد. الكود القديم كان بيتحقق من "هل السورة محمّلة؟" بالبحث عن رابط *ملف
السورة الكاملة* في الكاش — وهو رابط أصلاً **مش بيتخزّن خالص** لهذا النوع من
القرّاء، فكان دايمًا بيرجع "غير محمّلة" حتى لو كل آيات السورة اتحمّلت فعلًا
بنجاح 100%.

**الحل:** بقى فيه سجل محلي دقيق (`localStorage`) بيتسجّل فيه رقم كل سورة
فور اكتمال تحميلها فعليًا (سواء سورة واحدة أو "تحميل الكل")، وده اللي بيتقرأ
دلوقتي لعرض "محمّلة/غير محمّلة" — مش تخمين لاحق من شكل روابط الكاش.

**ملحوظة:** أي سور كنت حمّلتها فعلاً *قبل* هذا الإصلاح لن تظهر كـ"محمّلة"
تلقائيًا (لأن السجل المحلي الجديد بدأ فاضي)، لكن ملفاتها الصوتية نفسها لسه
موجودة على الجهاز ومحفوظة — لو ضغطت "تحميل" عليها تاني هيكتشف إنها موجودة
بالفعل ويسجّلها فورًا من غير أي تنزيل حقيقي إضافي (ثواني بس).

## تحديث: اختيار القارئ من المشغّل نفسه + تبسيط صفحة الصوتيات

### 1) اسم القارئ في شريط المشغّل بقى قابل للضغط
اضغط على اسم القارئ الظاهر في شريط التشغيل المصغّر أسفل صفحة القراءة (فوق
عنوان السورة مباشرة) — تفتح قائمة كاملة بكل قرّاء التطبيق (بالصور، وعلامة
✓ بنية على القارئ الحالي). اختيار قارئ جديد:
- يصبح فورًا هو "القارئ المختار" في كل أنحاء التطبيق.
- لو فيه سورة شغّالة حاليًا، تُعاد تلقائيًا بصوت القارئ الجديد من نفس السورة.

### 2) صفحة "الصوتيات" اتبسّطت
- اتشالت قائمة "كل القرّاء" الطويلة نهائيًا.
- بطاقة "القارئ المختار" بقت بس بتعرض صورة/اسم القارئ الحالي (مفيش قائمة
  اختيار هنا تاني — الاختيار بقى حصريًا من المشغّل نفسه زي فوق). الضغط على
  البطاقة يفتح مباشرة قائمة الـ ١١٤ سورة الخاصة بالقارئ (تحميل/استماع/تحميل
  الكل — نفس الشاشة اللي كانت موجودة بالفعل).
- قسم "القرّاء المحمّلون" فضل زي ما هو من غير تغيير.

## اختبار سريع

- على المتصفح العادي (بدون Capacitor): التطبيق يعمل بنفس سلوكه القديم تمامًا،
  ولن يظهر الحاجز إطلاقًا.
- على تطبيق أندرويد بعد `npx cap sync` و تثبيت الـ APK: أول فتح للتطبيق (بعد
  مسح بيانات التطبيق أو أول تثبيت) هيظهر الحاجز. اضغط "تحميل صفحات المصحف"،
  جرّب فصل الإنترنت أثناء التحميل للتأكد من ظهور رسالة الخطأ وإمكانية إعادة
  المحاولة، ثم افتح التطبيق في وضع الطيران بالكامل بعد اكتمال التحميل للتأكد
  إن كل الصفحات تُقرأ بدون أي مشاكل.

## تحديث سابق: تقليل حجم الـ APK — نقل رسم المصحف العادي وصوت الأذكار لاستضافة خارجية

### المشكلة
حجم الـ APK وصل لـ 218 ميجا. السبب الرئيسي: مجلد `quran-qcf4/` (رسم مصحف
المدينة العادي + خطوطه، ~148 ميجا) كان مضمَّنًا كملفات ثابتة داخل `www/`،
بالإضافة لملفي صوت الأذكار (`audio/azkar/sabah.mp3` و `masaa.mp3`، ~40 ميجا).

### الحل (النسخة السابقة)
استضيفت هذه الملفات خارج التطبيق:
- **رسم المصحف العادي (QCF4):** `github.com/Ziad-Alkamash/quran-qcf4`
  (نسخة/fork من المستودع الأصلي `MohamadHajjRabee/quran-qcf4`، عشان نضمن
  استمراريته تحت تحكّمنا)
- **صوت الأذكار:** `github.com/Ziad-Alkamash/mushaf-alashraf`
  (تحت `audio/azkar/`)

### التغييرات في الكود
- **`quran-api.js` (`getPageQCF4`)**: بدل القراءة من `quran-qcf4/pages/*.json`
  المحلي، بيجيب كل صفحة من `raw.githubusercontent.com/Ziad-Alkamash/quran-qcf4`
  عند أول فتح ليها، ويخزّنها فعليًا عبر `QuranOffline.cacheFetchJSON` (تخزين
  دائم على تطبيق أندرويد/آيفون المثبَّت عبر Capacitor Filesystem)، فتشتغل
  بدون إنترنت من ساعتها. على متصفح/PWA عادي، بترجع لنظام التخزين المؤقت
  القديم (`localStorage`، `cachedFetchJSON`).
- **`quran-offline.js`**: أُضيفت دالة عامة جديدة `cacheFetchJSON(url, relPath)`
  (نفس فكرة تحميل نص الآيات، بس لملف واحد عند الحاجة بدل الـ604 دفعة واحدة).
- **`app.js` (خطوط QCF4)**: `QCF4_FONT_BASE` بقى يشير مباشرة لـ
  `cdn.jsdelivr.net/gh/Ziad-Alkamash/quran-qcf4@main/fonts-woff2/` (خط لكل
  صفحة يتحمّل عند فتحها فقط، ومتصفح/WebView التطبيق بيخزّنه في الكاش
  المحلي بعد أول تحميل بفضل رؤوس Cache-Control طويلة المدى اللي jsDelivr
  بيبعتها).
- **`app.js` (صوت الأذكار)**: `AZKAR_AUDIO_FILES` بقت روابط
  `cdn.jsdelivr.net/gh/Ziad-Alkamash/mushaf-alashraf@main/audio/azkar/...`،
  وأول تشغيل بيتحمّل الملف ويتخزّن فعليًا عبر `QuranAudioOffline` (نفس نظام
  تخزين ملفات القرّاء الموجود بالفعل)، فيشتغل بدون إنترنت من المرة الجاية.
- **`sw.js`**: `CACHE_NAME` اتحدّث لـ `v235` عشان كل التعديلات دي توصل فعليًا
  لأي نسخة مثبَّتة من قبل.

### خطوة نُفذت في النسخة السابقة
لازم تتشال المجلدات دي فعليًا من مشروعك (مش بس من الكود، لازم تتشال
كملفات) قبل `npx cap sync android`، وإلا حجم الـ APK مش هيقل خالص حتى لو
الكود بقى بيحمّلهم من أونلاين:
- `www/quran-qcf4/` بالكامل
- `www/audio/azkar/sabah.mp3` و `www/audio/azkar/masaa.mp3` (فولدر
  `audio/adhan/` سيبه زي ما هو، لسه محلي)

### ملاحظة عن النسخة السابقة
صفحات القرآن (نص الآيات + رسم QCF4) وصوت الأذكار بيتخزّنوا في تخزين
التطبيق الدائم (Capacitor Filesystem) — مضمونين 100% بدون إنترنت بمجرد ما
يتفتحوا/يتشغّلوا مرة واحدة. خطوط QCF4 بترجع للكاش
العادي بتاع WebView (مش Filesystem)، وده أضعف شوية من ناحية الضمان (ممكن
نظام التشغيل يمسحه في حالات نادرة زي امتلاء المساحة الشديد)، بس هو نفس
الأسلوب اللي كان شغّال زمان قبل ما نضيف التضمين المحلي، ومناسب هنا لأن حجم
كل خط صغير والتحميل بيحصل تلقائيًا تاني لو اتمسح.
