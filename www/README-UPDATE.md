# تحديث: الانضمام للختمة الجماعية بموافقة المنشئ

1. Firebase Console → Firestore → Rules: امسح القديم والصق `firestore.rules` → Publish.
2. على الراسبيري باي: استبدل `server.js` ثم `sudo systemctl restart khatma-push`.
3. في مشروع التطبيق: استبدل `khatma-group.js` ثم `npx cap sync android` وابني APK جديد.

# تحديث: استرجاع الختمات الجماعية بعد مسح التطبيق/بياناته (كود الاسترجاع)

ميزة جديدة: أي مستخدم بيقدر يسترجع كل الختمات الجماعية اللي كان فيها أو
منشئها (لكن مش الفردية، دي محفوظة على الجهاز بس ومش هترجع، وده مقصود) لو
مسح التطبيق أو بياناته أو نزّله على جهاز تاني، عن طريق "كود استرجاع" بيتولّد
تلقائيًا وبيتعرضله مرة واحدة (شاشة الترحيب + صفحة "الملف الشخصي").

**خطوة إجبارية عشان الميزة دي تشتغل (مرة واحدة بس، لكل مشروع Firebase):**

1. Firebase Console → Authentication → Sign-in method → فعّل **Email/Password**
   (لو ملقيتوش في القايمة، دوس "Add new provider" واختاره، وفعّل الـ Toggle
   بس، مفيش أي إعداد إضافي مطلوب).
2. Firebase Console → Firestore → Rules: تأكد إن `firestore.rules` المحدّث
   متلصق (نفس الملف بتاع الخطوة اللي فوق، الميزة دي ما غيّرتش في القواعد
   نفسها، بس الملف فيه تعليق توضيحي جديد).
3. في مشروع التطبيق: استبدل `khatma-group.js`، `firestore-rest.js`،
   `index.html`، `khatma-group.css`، `i18n.js` بالنسخ الجديدة، ثم
   `npx cap sync android` وابني APK جديد.

**ملحوظة مهمة:** المستخدمين اللي عندهم بروفايل قديم من قبل التحديث ده (بمعنى
عندهم `users/{uid}` documents موجودة بالفعل) مش هيتولّدلهم كود استرجاع
تلقائيًا (الكود بيتولّد بس أول مرة يتعمل فيها البروفايل). لو حابب تديهم
الميزة دي كمان، سهل: في صفحة "الملف الشخصي"، في زرّ "إظهار كود الاسترجاع" —
أول ضغطة عليه للمستخدمين دول هتولّدلهم كود جديد تلقائيًا (نفس آلية
"تجديد الكود").
